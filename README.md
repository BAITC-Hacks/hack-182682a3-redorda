# RedOrda — HackAlem AI: Beeline Tariff Marketing Campaigns

Репозиторий команды RedOrda. Выбранный кейс — **агент планирования тарифных маркетинговых кампаний**. Все данные и показатели кейса синтетические; они не отражают реальные данные Beeline.

**Статус:** кейс выбран, требования зафиксированы; реализация агента ещё не добавлена.

## Задача

Для аудитории из **23 441 абонента** построить агента, который исследует данные, проводит пилотные кампании и возвращает план из **1–10 кампаний**. Для каждой кампании агент выбирает:

- **кому** предложить переход: сегмент по ARPU, потреблению данных и/или текущему тарифу;
- **что** предложить: один из 21 тарифа;
- **как** связаться: `push`, `sms`, `digital_ads` или `call`.

Цель — максимизировать чистый эффект: **прирост ARPU уникальных абонентов минус стоимость всех контактов**, включая пилотные. История смен тарифов относится к другой выборке, поэтому эффект для текущей аудитории нужно оценивать, в том числе через `env.run_pilot(...)`. Результаты локальной мок-среды не следует зашивать в решение.

## Входные данные и интерфейс

Организаторы предоставляют объект `env` с профилями абонентов (`env.customer_profile`), тарифами, каналами, остатками лимитов и результатами пилотов. Агент должен находиться в `agent.py`:

```python
class Agent:
    def act(self, env) -> list[dict]:
        # env.run_pilot(...) доступен для проверки гипотез.
        return [
            {
                "campaign_name": "Example campaign",
                "filter_arpu_segment": "HIGH",
                "target_tariff": "tariff_10",
                "channel": "sms",
            }
        ]
```

Пример выше показывает **формат ответа**, а не готовую стратегию. Обязательные поля кампании — `target_tariff` и `channel`; фильтры сегмента опциональны. В пакете участника также предусмотрены `customer_profile.csv`, история смен тарифов, трафика и ARPU, справочники тарифов и признаков.

## Ограничения

| Параметр | Лимит |
| --- | ---: |
| Кампании | не более 10 |
| Абоненты в одной кампании | не более 5 000 |
| Контакты суммарно, включая пилоты | не более 15 000 |
| Общий бюджет, включая пилоты | 100 000 у. е. |
| Пилоты | не более 20, по 10–200 абонентов |
| Время работы `Agent.act` | не более 10 минут |

Один абонент учитывается в результате только один раз. Агент должен использовать пилоты и опираться на их результаты, не превышать лимиты и корректно работать при ошибках внешнего LLM API, если такой API будет использоваться. Доступ к скрытым данным среды в обход публичного интерфейса запрещён.

## Что нужно сдать

1. `agent.py` с классом `Agent` и методом `act(env)`, который возвращает 1–10 корректных кампаний.
2. `submission.csv`, воспроизводимый командой `python make_submission.py`.
3. `requirements.txt`, если понадобятся дополнительные библиотеки.
4. Код и документацию подхода в этом репозитории.

После получения стартового пакета организаторов проверять решение командами `python local_eval.py`, `python local_eval.py --runs 10` и `python make_submission.py`. Эти команды пока не запускаются: стартовый пакет и реализация агента в репозитории отсутствуют.
