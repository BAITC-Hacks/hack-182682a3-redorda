# Вход в Janymda

## Назначение

Гость при открытии любого адреса фронтенда видит страницу входа. После успешной авторизации пользователь попадает на запрошенную страницу и работает с защищённым API в рамках Django-сессии. Кнопка выхода завершает сессию и возвращает на вход.

## Контракт API

Опубликованная схема `https://hack.1ge.kz/api/schema/` определяет:

- `GET /api/v1/auth/me/` → `{ authenticated, user, csrf_token? }`;
- `GET /api/v1/auth/csrf/` → `{ csrf_token }` и cookie `csrftoken`;
- `POST /api/v1/auth/login/` с `{ username, password }` и `X-CSRFToken` → состояние сессии;
- `POST /api/v1/auth/logout/` с `X-CSRFToken` → состояние гостя.

Все запросы выполняются на том же origin с cookie. Перед каждым изменяющим запросом клиент получает CSRF-токен, если актуального токена нет; после входа и выхода использует новый токен из ответа. Пароль остаётся только в памяти формы и не сохраняется в браузерном хранилище. Ошибки API читаются из `{ error: { code, message, fields } }`.

## Фронтенд

`App` хранит состояние проверки сессии и пользователя. При загрузке вызывает `auth/me/`. Пока запрос идёт, показывает состояние загрузки. Гостю вместо основного интерфейса показывает страницу входа; адрес исходной страницы сохраняется в памяти навигации. После успешного входа восстанавливает этот адрес. Если проверка сессии не удалась из-за сети или ошибки сервера, показывает ошибку с повтором запроса, а не форму входа.

Страница входа использует существующий логотип Janymda, поле логина, поле пароля, кнопку входа и сообщения об ошибке. Во время отправки форма блокирует повторный запрос. Основной интерфейс показывает имя вошедшего пользователя и кнопку выхода. На маленьком экране выход остаётся доступным. Ответ `401` или `403` с кодом `not_authenticated` на защищённом запросе переводит приложение в состояние гостя.

## Проверка

Проверить загрузку сессии, вход с неверным паролем, успешный вход с возвратом на исходную страницу, обновление страницы, выход, истечение сессии и ошибку сети. Выполнить `make check` и осмотреть десктопную и мобильную версию в браузере.

## Зависимость

На опубликованном сервере методы авторизации уже присутствуют, а неавторизованный `GET /api/v1/meta/` возвращает `403`. В локальном `main` backend пока не содержит этих методов. Фронтенд реализуется по опубликованной схеме; полноценный локальный сквозной вход станет возможен после синхронизации backend-кода с ней.
