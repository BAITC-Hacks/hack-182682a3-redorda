# Разработчик 3 — рабочий интерфейс и живая команда

**Зона:** `frontend/`. Ветка `codex/team-frontend`, отдельный worktree.
React 18.2, TypeScript, Vite; сохранять существующих пиксельных персонажей и отрисовку.
Общий порядок: [план команды](00-team-plan.md); целевой контракт: [team-contract.md](../team-contract.md).

## Текущая точка — main `b2e5bb3`

Уже реализованы сессии/CSRF, создание, start/cancel, polling событий, результаты и CSV.
`AgentPets.tsx` показывает Жана, Дану, Айю и Бека; `choreography.ts` пока переключает
декоративные сценки по таймеру. Доработать эти компоненты, не собирать приложение заново.

## Этап 1 — один запуск, два представления

- Вынести состояние выбранного запуска, задач, событий и результатов в общий React hook/context.
- Добавить «Рабочий стол / Живая команда»: один `run_id`, один polling, одинаковые данные и действия.
- Сохранить действующие авторизацию, запуск, отмену и экспорт; переключение режима не создаёт запуск.
- Постоянно показывать расходы/остаток бюджета, контакты, пилоты, статус; прогноз и измеренный эффект
  подписывать отдельно. Неизвестные значения показывать как отсутствующие, не заменять нулём.

## Этап 2 — события управляют персонажами

- Подключить задачи и передачи из целевого контракта; заменить цикл сцен реакциями на события API.
- Закрепить соответствие: Бек — руководитель, Дана — аналитик/финансист, Айя — экспериментатор,
  Жан — контролёр. У Даны явно показывать активную роль; допустим отдельный пятый персонаж.
- Начало задачи → работа, передача → ходьба с папкой, ошибка → остановка с причиной;
  завершение показывать только после серверного подтверждения. Таймер допустим для движения спрайта.
- Клик по персонажу/папке открывает общую панель: задача, входные данные, результат, доказательства.
- Существующая пауза/скрытие персонажей управляет только анимацией; расчёт останавливает cancel.

## Этап 3 — общение и проверка

- Через API-клиент подключить `explain`, `compare`, `create_plan`: кнопки и текстовое обращение,
  статус команды, ответ со ссылками на реальные данные. Недоступные команды явно отключать.
- Использовать контракт backend; не выполнять расчёты LLM в браузере и не придумывать API.
- После перезагрузки восстановить задачи/события выбранного запуска без повторного старта,
  повторной команды и проигрывания старых передач как новых. Сохранить дедупликацию и курсор событий.
- Проверить мобильность, клавиатуру, reduced motion, потерю сессии/сети, ошибку и отмену;
  персонажи не перекрывают управление обычным приложением. Обновить типы по OpenAPI.

**Готово:** реальный запуск и команды доступны в обоих режимах; действия персонажей соответствуют
сохранённым событиям, данные совпадают после переключения и перезагрузки, CSV скачивается.
Выполнить `npm run build`, общий `make check` и браузерный сценарий на реальном API.

**Инструкция ИИ:** прочитай `AGENTS.md`, `README.md`, оба контракта и общий план; меняй только
`frontend/`, согласуй новые поля с backend-разработчиком. Не подключай OpenAI из браузера.
