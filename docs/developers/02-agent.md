# Разработчик 2 — AI-агент и расчёт кампаний

**Зона:** `packages/campaign_engine/`, корневой `agent.py`, `scripts/run_official.py`. Чистый Python без зависимости от Django.

1. **Основа:** изучить публичный пакет Beeline; реализовать `Agent.act(env)`, анализ истории и базовую стратегию с пилотами. Передавать бэкенду события и результаты через согласованный интерфейс.
2. **Рабочий сценарий:** ранжировать гипотезы, адаптивно проводить пилоты, учитывать шум и выбирать тариф, аудиторию и канал. Подключить GPT-6 через Responses API для гипотез; при сбое использовать расчётную стратегию.
3. **Сдача:** проверить бюджет, пересечения аудиторий и все лимиты; выполнить `local_eval --runs 10`, сформировать воспроизводимый `submission.csv` и сравнить с базовым агентом. Цель — устойчивый положительный эффект, результат подтвердить прогонами.

**Лимиты:** бюджет 100 000; 15 000 контактов с пилотами; до 20 пилотов по 10–200 клиентов; 1–10 кампаний до 5 000 клиентов; до 10 минут. Один клиент учитывается один раз. Скрытые данные среды не читать.

В выданном CSV отсутствует текущий тариф у 95 клиентов, ARPU-сегмент у 5, сегмент интернета у 110. Сохранять пропуски, не придумывать значения; `UNKNOWN` в сводке не является разрешённым фильтром кампании.

**Готово:** один движок обслуживает веб и судейский `Agent.act`; расходы и эффект вычисляются кодом. Повторная генерация submission с seed 42 воспроизводится; свежие ответы LLM не должны нарушать эту проверку.

**Инструкция ИИ:** прочитай `README.md`, `docs/api-contract.md`, это ТЗ и `data/participant-kit/PARTICIPANT_GUIDE.md`. Работай в `codex/dev2-agent`, по одному этапу. Используй только публичные методы среды. Не меняй оценщик организаторов и не подгоняй константы под мок. Тестируй лимиты, fallback и воспроизводимость.
